# 故障闭环草稿

## 前提

确认服务、影响范围、值班联系人和访问权限。记录时间线，证据保留在所属环境。

## 处理步骤

1. 确认用户影响、开始时间和是否仍在扩大。
2. 核对近期变更，收集指标、事件和脱敏日志位置。
3. 为每个假设记录证据、排除条件和下一步验证，避免无依据反复重启。
4. 选择已验证的恢复手册，确认执行范围、退出条件和回滚方法。
5. 恢复后验证业务链路，并按约定观察窗口确认稳定。
6. 使用 templates/incident.md 复盘，形成带责任人、期限和验收标准的改进项。

## 执行与退出

具体诊断命令和恢复操作需按服务补齐。操作超出范围、出现新影响或证据不足时停止并升级处理。

## 验证记录

记录恢复前后证据、影响时长、实际根因与仍未确认事项。本文件未经真实或演练环境验证。
